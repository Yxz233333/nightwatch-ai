该文是 AWS 官方技术博客系列第一篇，面向没有剖析经验的读者，介绍如何系统分析模型推理性能、定位耗时环节。作者以 AWS Trainium 芯片及其开源 PyTorch 后端 TorchNeuron 为平台，演示用 torch.profiler 配合 NeuronConfig 采集干净的性能轨迹，读取 key_averages() 表找出占用 Neuron 设备时间最多的算子，并借助 Neuron Explorer 追踪单个算子从框架调度、运行时排程到硬件执行的全过程。文中以 RMSNorm 的三种实现做对比，说明融合算子与 torch.compile 可减少设备时间。

  • 介绍用 NeuronConfig 配置 torch.profiler，采集设备与运行时数据流并导出轨迹。
  • 演示按 self_privateuse1_time_total 排序 key_averages() 表，定位设备耗时算子。
  • 对比朴素算子、torch.rms_norm 与 torch.compile 三种 RMSNorm 实现的设备时间。
